## 五、开发过程中修复的 3 个真实缺陷

### 1. SQLite `database is locked`（阻塞级）
**现象**：`POST /api/chat` 返回 500。
**根因**：SSE 生成器长时间持有读连接，管理员此时上传文档 / 新建会话就会写锁冲突。SQLite 默认 `rollback journal` 模式读写互斥。
**修复**：`PRAGMA journal_mode=WAL` + `PRAGMA synchronous=NORMAL` + 连接 `timeout=15`（等价的 busy_timeout）。读写不再阻塞，偶发写写冲突自动重试 15 秒。

### 2. 中文提示在重定向里变成乱码
**现象**：`?msg=上传成功` 在浏览器地址栏显示为 `%E4%B8%8A...`，部分客户端截断。
**根因**：中文直接拼进 `Location` 响应头，不符合 RFC 对 header 的 ASCII 要求。
**修复**：统一 `quote(msg)` 编码后再拼接，服务端渲染时自动还原。同时排查确认 urlencoded 表单路径本身没有问题（Starlette 内部 latin-1 后 `unquote_plus(utf-8)`，浏览器发的是百分号编码，正常）。

### 3. 提示词回滚测试误判
**现象**：回滚用例偶发 FAIL。
**根因**：测试脚本用正则抓页面第一个 `activate` 链接，但列表按 id 倒序，抓到的是刚创建的测试模板自身。
**修复**：改为按库里 `name LIKE '默认模板%'` 精确定位 id 再回滚。（属测试用例缺陷，应用逻辑无误，但已记录以免后续误判。）

## 六、关键设计决策（答辩可直接讲）

1. **错误必须分层**。SSE 一旦开始推流，HTTP 状态码就改不了了。所以「参数空、会话不属于本人、知识库为空」这类本地能 100% 判定的错误全部前置校验，返回 4xx + JSON；只有 Embedding / 大模型这类外部依赖的失败才走流内 `error` 事件，并**自动降级为检索原文展示**——用户永远拿得到东西，而不是看到一个红叉。
2. **`3002 未命中` 与 `4001 模型失败` 刻意不算失败**。前者是知识库边界，应如实说"未收录"；后者是外部依赖故障，应降级。把这两类当错误抛给用户是 RAG 系统最常见的体验事故。
3. **向量不建独立库**，直接存 `kb_chunks.embedding` BLOB，numpy 全量余弦。几十份文档的量级下，这比引入 FAISS/向量数据库少一整套索引重建与删除一致性问题。
4. **提示词存库 + 多版本**，而不是写死在 `config.py`。管理员改完下一个请求就生效，且能一键回到上一版——这是"生产可用"和"玩具"的分界线。
5. **审计不是日志**。`messages` 表冗余 `citations / model / degraded / prompt_tokens / completion_tokens / latency_ms`，管理员能定位"这条回答是哪次检索、哪个模型、花了多少 token"，出问题可复盘。
6. **没 Key 也能完整演示**。LLM 与 Embedding 双降级：本地哈希向量 + 检索原文拼接 + 按句切分模拟流式。答辩现场不需要联网、不需要买 key。

## 八、已知限制（诚实清单）

1. 鉴权为演示级：无 Refresh Token、无强制改密、无登录失败锁定。
2. SQLite 单机：WAL 兜底并发，不适合多实例；生产应换 PostgreSQL + pgvector。
3. 向量全量载内存：切片超 10 万会拖慢启动。
4. 违规标记纯人工，未做话术自动识别。
5. 无 OCR：扫描件 PDF 提取不到文本，上传时会明确报错。
6. 提示词切换无灰度、无变更审计流水（仅记 `updated_by/updated_at`）。

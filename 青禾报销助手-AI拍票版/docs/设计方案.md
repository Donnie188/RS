# 设计方案 · 青禾报销助手 AI 拍票版

## 一、系统架构

```
员工端小程序（拍票/填单/查询）
        ↓
   API 网关
        ↓
报销服务 ←→ AI 服务（OCR识别/科目推荐/合规预检）
        ↓
主管端审批 ←→ 财务端复核
```

## 二、核心流程

### 现状流程（传统手工报销）
员工手填单 → 贴发票 → 跑主管签字 → 跑财务复核 → 财务打款
**痛点**：平均周期 5–7 天，退单率 20%

### 数智化转型后流程
员工拍票 → AI 识别金额/商家 → 自动推荐科目 → 提交 → 主管审批 → 财务复核 → 打款
**提升**：平均周期 1–2 天，退单率降至 5%

## 三、AI 能力清单

| AI 能力 | 作用 |
| --- | --- |
| 发票 OCR | 自动提取金额、商家、税号、日期 |
| 科目推荐 | 根据商家和金额推荐报销科目 |
| 合规预检 | 招待费超阈值、专票金额过小自动提示 |

## 四、技术栈

- 前端：微信原生小程序
- 后端：Node.js + MySQL
- AI：第三方 OCR API
- 部署：云服务器

## 五、权限设计

- 员工：只能看自己的单据
- 主管：审批本部门单据
- 财务：复核全部单据，标记打款

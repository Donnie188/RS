# MVP 人工确认点说明（合规设计，共 3 处）

本 MVP 按“人机协同”原则设计，以下 3 处人工确认/审核点为一期硬性要求，任何环节不得由 AI 自动越过：

## 确认点①：报销草稿确认（员工端）
- **位置**：员工聊天页确认卡（templates/chat.html 的 draft-confirm 卡片）
- **触发**：Agent 调用 `create_draft` 后立即发出 `pending_draft` 事件并强制中断执行循环
- **机制**：确认动作由 `/api/drafts/{id}/confirm` 接口直接完成（**不经模型决策**），取消同理
- **保护**：服务端状态机 R1~R7——check_id 凭证一次性防重放、未确认草稿不可提交、提交幂等（R7 重复确认返回原单号）

## 确认点②：派单确认（店长端，建议版）
- **位置**：店长工作台（一期为建议版：AI 给出按技能/位置/负载加权的派单建议）
- **触发**：AI 生成派单建议后，店长一键确认方才生效
- **保护**：建议与确认均留痕（tool_calls 审计日志），责任主体始终是店长

## 确认点③：管理员审核（管理后台）
- **位置**：管理后台“知识库管理 / 提示词模板”页
- **触发**：知识库上传删除、系统提示词修改仅管理员（admin 角色）可操作
- **保护**：JWT + RBAC 接口级权限校验；全部操作写审计日志；提示词存数据库即时生效，可随时回滚默认模板

## 对应代码
| 确认点 | 模块 |
|---|---|
| ① | app/agent/loop.py（中断）、app/main.py（confirm/cancel 接口）、app/agent/tools.py（STATE_TOOLS） |
| ② | 派单建议接口（一期建议版） |
| ③ | app/main.py admin 路由 + app/auth.py RBAC 依赖 |
